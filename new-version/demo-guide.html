REACHBLOOM / FRONTEND DEMONSTRATION

Try the connected journey

Use fictional information only. Data stays in this browser. Roles, login, review and ownership are simulated; this is not secure authentication or identity verification.

One browser, one fictional workspace

This demo uses localStorage for fictional records and sessionStorage for its simulated signed-in account. Use a local server so every page shares the same origin. Roles in browser storage are editable and provide no real security.

  1. Sign in as owner@example.com using BloomDemo!; choose Business Owner.
  2. Apply to list a new fictional business. Its status is Pending Review and it is hidden publicly.
  3. Log out. Open the separate administrator demo entry, use BloomDemo! and enter the review workspace.
  4. Inspect the application and approve it. Explore Businesses will now show it.
  5. Suspend it: it disappears from the directory and its direct storefront shows an unavailable message.
  6. Log out. Sign in as customer@example.com using BloomDemo!, save a business, then visit the customer dashboard.
  7. As the owner, open Savanna Kitchen and submit a claim. As the demo administrator, review and approve it. Savanna then appears in that owner’s workspace.

Owner and customer roles are fixed by the demo account record. Choosing a different login account type will not change the role. Registration creates only a synthetic browser account, with the same public demo passphrase; do not enter a real password.

Administrator access is intentionally a separate documented scenario. Its entry is a simulation, not a protected production portal.
